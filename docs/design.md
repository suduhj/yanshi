# 设计规范

## 界面方向

第一阶段采用极简工具风格，优先稳定、清晰和低干扰。

## 页面原则

- 首页直接是任务工作台，不做营销页。
- 信息密度适中，优先展示标题、类型、系统优先级、状态、截止时间。
- 交互以原生表单和 Server Actions 为主，减少前端状态复杂度。
- 色彩保持中性，只在待确认、今天等状态上使用少量强调色。
- 首页品牌使用“砚时”，首屏展示寓意“于书砚之间，理清每日之事。”。
- 首页按执行逻辑分为“待确认 / 今日必须完成 / 今日要做 / 每日任务 / 持续推进任务 / 其他任务 / 已完成任务”。
- “今日必须完成”强调截止时间驱动，“今日要做”强调用户手动安排，“每日任务”强调当天打卡式完成。
- 首页在存在待确认任务时展示“晨间回砚”，帮助用户先复盘已经过截止时间的任务，再安排今天。
- 顶部统计卡片都是可点击入口，点击后切换到对应分类并滚动到任务列表。
- 首页在任务分区前展示轻量“提醒建议”，只在存在提醒时出现。
- 表单错误在字段附近用简短中文提示呈现，顶部显示“请检查任务信息”。
- 成功反馈使用页面顶部轻量提示，不使用弹窗打断操作。
- 新增任务表单提供自然语言描述输入和“解析填入”按钮，AI 只生成草稿，用户检查后再点击“添加任务”。
- 第二阶段首页增加紧凑的“今日小结”，位于提醒建议附近，用于复盘今天完成、推进、推迟和重新安排的任务。
- “生成 AI 回顾”必须由用户主动点击，不在页面打开时自动调用 AI。

## 组件约定

- 表单控件使用统一边框和紧凑高度。
- 任务列表按系统优先级、截止时间和状态排序。
- 新增任务表单不出现手动优先级选择。
- 新增和编辑表单包含“加入今日计划”“这是每日任务”“这是大跨度任务 / 需要持续推进”三个布尔选项。
- 编辑任务使用独立编辑页，带出原任务内容后再保存。
- 删除操作使用浏览器确认，确认后再提交删除。
- 任务卡片展示标题、类型、系统优先级、状态、截止时间、距离截止天数、下一步动作和今日/每日/持续推进标记。
- 任务卡片提供完成、加入今日/移出今日、推迟、编辑、删除等操作；每日任务提供“完成今日”按钮。
- 持续推进任务提供“今日推进完成”“更新下一步”“标记整个任务完成”，今日推进完成不等同于整个任务完成。
- 删除是危险操作，视觉上弱于主要处理按钮，避免每张卡片都出现强红色干扰。
- 空状态保持紧凑，减少空分区造成的滚动负担。
- 操作按钮保持文字明确，不使用装饰性说明文案。
- 提醒建议保持紧凑列表样式，使用少量颜色区分需要确认、今天关注和补充动作。
- 提醒建议的操作入口必须能跳到具体任务，并短暂高亮对应任务卡片。
- 提醒建议提供“开启通知”按钮；授权后显示简短状态，拒绝权限时不反复打扰。
- 今日小结空状态保持简短，不增加明显滚动负担。
- AI 回顾以文本建议形式出现，语气温和具体，不伪装成自动处理结果。
- 任务复盘记录第一版优先展示在编辑页，避免任务卡片继续变重。

## 复盘统计

- `/stats` 页面用于查看复盘统计，不替代首页任务工作台。
- 页面展示近 7 天概览、趋势、任务类型分布、来源分布和最近复盘记录。
- 图表第一版使用轻量横向条和紧凑列表，不引入复杂交互。
- 空状态保持简短，不增加额外说明卡片。
