# E1/E2 数据可视化设计规格

## 背景

砚时当前已经有 `TaskEvent` 复盘历史，用于记录完成任务、完成每日任务、今日推进、更新下一步、推迟截止时间和晨间确认等关键动作。第三阶段路线图中，A1 自动备份之后的下一步是 E1/E2 数据可视化，用已有历史数据帮助用户复盘完成趋势和精力分布。

本规格覆盖第一版统计页。第一版不引入 Recharts、Chart.js 等新图表库，使用现有 React、TypeScript 和 Tailwind CSS 实现轻量可读的统计视图。

## 目标

- 新增 `/stats` 复盘统计页。
- 展示近 7 天任务处理趋势。
- 展示任务类型分布。
- 展示任务来源分布。
- 展示最近复盘记录。
- 为后续 AI 今日建议提供稳定的本地统计基础。

## 非目标

- 不引入新图表依赖。
- 不新增数据库表或 Prisma 迁移。
- 不做 AI 分析。
- 不做导出。
- 不做复杂时间范围筛选。
- 不改变首页主任务工作流。

## 数据来源

第一版使用两类数据：

- `TaskEvent`：统计近 7 天完成、推进、推迟和重新安排事件。
- `Task`：统计当前任务的类型和来源分布。

任务事件按已有中国日期键 `chinaDateKey` 聚合。当前任务的来源分布基于 `source` 字段；空来源归为“未填写来源”。

## 统计口径

### 时间范围

第一版固定展示近 7 天，包含今天。日期计算必须复用 `src/lib/tasks/domain.ts` 中的中国时间工具，避免服务器时区差异。

### 事件分组

沿用现有 `summarizeTaskEventsByType` 的分类语义：

- 完成：`task_completed`、`daily_completed`、`morning_confirmed_done`
- 推进：`progress_completed`
- 推迟/重新安排：`due_postponed`、`marked_unfinished_today`
- 更新下一步：`next_action_updated`

趋势图第一版重点显示完成、推进、推迟/重新安排三类。更新下一步进入概览统计，但不单独占趋势主视觉。

### 类型分布

任务类型分布基于当前 `Task` 列表，按 `type` 聚合数量，并使用 `TASK_TYPE_LABELS` 显示中文名称。

### 来源分布

来源分布基于当前 `Task` 列表，按 `source` 聚合数量。第一版只展示数量最多的前 8 个来源，其余归为“其他来源”。

## 页面设计

`/stats` 页面采用工具型布局，不做营销页。

页面结构：

1. 顶部导航：返回任务列表。
2. 页面标题：复盘统计。
3. 概览卡片：近 7 天完成、推进、重新安排、今日记录。
4. 近 7 天趋势：按日期展示横向条，每天显示完成、推进、重新安排数量。
5. 类型分布：紧凑列表 + 比例条。
6. 来源分布：紧凑列表 + 比例条。
7. 最近复盘记录：最近 10 条事件摘要和中国时间。

空状态保持简短：

- 没有事件时提示“还没有复盘记录。完成、推进或重新安排任务后，这里会出现趋势。”
- 没有任务时提示“暂无任务数据。”

## 技术设计

新增 `src/lib/tasks/stats.ts`，负责纯统计逻辑：

- 生成近 7 天中国日期键序列。
- 按日期聚合 `TaskEvent`。
- 生成概览数字。
- 生成任务类型分布。
- 生成任务来源分布。
- 截取最近复盘记录所需数据。

新增 `src/lib/tasks/stats.test.ts`，覆盖：

- 近 7 天日期序列包含今天并按时间升序。
- 事件按中国日期键聚合。
- 完成、推进、重新安排分类正确。
- 空数据返回稳定结构。
- 类型分布使用中文标签。
- 来源分布处理空来源和前 8 个来源限制。

新增 `/stats` 页面：

- Server Component 直接读取 Prisma 数据。
- 调用 `buildStatsDashboardData(tasks, events, now)` 得到展示模型。
- 使用 Tailwind 绘制数字卡片、横向条和列表。
- 不在客户端维护图表状态。

## 首页入口

第一版可以在首页顶部区域加入一个轻量文本入口“复盘统计”，指向 `/stats`。该入口不改变任务分区、提醒建议和今日小结布局。

如果实现时发现首页入口会增加视觉负担，可以先只保留 `/stats` 路由，后续再接入导航。

## 错误处理

- 统计页读取数据失败时交给 Next.js 默认错误边界。
- 统计函数对空数组返回空统计模型，不抛错。
- 未知任务类型使用原始类型值展示，避免历史脏数据导致页面崩溃。
